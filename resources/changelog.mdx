## Version 2.0.0
*Released: October 1, 2023*

### 💥 Breaking Changes

<Warning>
  **Migration Required**: This version includes breaking changes. Review the migration guide below.
</Warning>

<AccordionGroup>
  <Accordion title="Authentication Changes">
    **OAuth 2.0 Enhancements:**
    - Required scopes are now more granular
    - Token endpoint moved from `/auth/token` to `/oauth/token`
    - New mandatory `X-Request-ID` header for all requests
    - Enhanced certificate validation requirements
    
    **Migration Steps:**
    ```bash
    # Before (v1.x)
    POST /auth/token
    
    # After (v2.0+)  
    POST /oauth/token
    ```
    
    **New required scopes:**
    ```json
    {
      "old_scope": "accounts",
      "new_scopes": ["accounts:read", "accounts:detail"]
    }
    ```
  </Accordion>
  
  <Accordion title="Response Format Changes">
    **Standardized Response Structure:**
    All APIs now return data in a consistent wrapper format:
    
    ```json
    // Before (v1.x)
    {
      "accounts": [...],
      "totalCount": 10
    }
    
    // After (v2.0+)
    {
      "data": {
        "accounts": [...]
      },
      "links": {
        "self": "https://api.adcb.com/v1/accounts",
        "next": null
      },
      "meta": {
        "totalCount": 10,
        "pageCount": 1
      }
    }
    ```
  </Accordion>
  
  <Accordion title="Error Format Updates">
    **RFC 7807 Compliance:**
    Error responses now follow Problem Details standard:
    
    ```json
    // Before (v1.x)
    {
      "error": "Invalid account ID",
      "code": "INVALID_ACCOUNT"
    }
    
    // After (v2.0+)
    {
      "error": {
        "type": "https://api.adcb.com/errors/invalid_account",
        "title": "Invalid Account",
        "status": 400,
        "detail": "The specified account ID is not valid",
        "instance": "/v1/accounts/invalid-id",
        "trace_id": "abc-123-def-456"
      }
    }
    ```
  </Accordion>
</AccordionGroup>

## Migration Guides

### Migrating from v1.x to v2.0

<Steps>
  <Step title="Update Authentication">
    Change token endpoint and add new required headers
    ```diff
    - POST /auth/token
    + POST /oauth/token
    + X-Request-ID: unique-request-id
    ```
  </Step>
  <Step title="Update Response Parsing">
    Modify code to handle new response wrapper format
    ```diff
    - const accounts = response.accounts;
    + const accounts = response.data.accounts;
    ```
  </Step>
  <Step title="Update Error Handling">
    Adapt error handling for new RFC 7807 format
    ```diff
    - console.log(error.message);
    + console.log(error.error.detail);
    ```
  </Step>
  <Step title="Review Scopes">
    Update OAuth scopes to new granular permissions
    ```diff
    - scope: "accounts payments"
    + scope: "accounts:read payments:write"
    ```
  </Step>
</Steps>

### Breaking Change Policy

**Our Commitment:**
- 6 months advance notice for breaking changes
- 24 months support for deprecated versions
- Clear migration documentation and tools
- Sandbox environment for testing migrations

**What We Consider Breaking:**
- Removing API endpoints
- Changing required parameters
- Modifying response data structure
- Authentication/authorization changes

**What We Don't Consider Breaking:**
- Adding new optional parameters
- Adding new response fields
- Bug fixes and security updates
- Performance improvements

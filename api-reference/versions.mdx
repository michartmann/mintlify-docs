## Breaking Changes Guide

### v1.3.x → v2.0.0 Migration

<Steps>
  <Step title="Update Authentication">
    **Change OAuth endpoints and headers**
    
    ```diff
    // Before (v1.3.x)
    - POST https://auth.adcb.com/auth/token
    
    // After (v2.0.0)
    + POST https://auth.adcb.com/oauth/token
    + X-Request-ID: unique-request-id (required)
    ```
  </Step>
  
  <Step title="Update Response Parsing">
    **Handle new response format**
    
    ```diff
    // Before (v1.3.x)
    - const accounts = response.accounts
    
    // After (v2.0.0)  
    + const accounts = response.data.accounts
    + const pagination = response.meta
    + const links = response.links
    ```
  </Step>
  
  <Step title="Update Error Handling">
    **Implement RFC 7807 error format**
    
    ```diff
    // Before (v1.3.x)
    - if (error.code === 'INVALID_ACCOUNT') {
    -   console.log(error.message)
    - }
    
    // After (v2.0.0)
    + if (error.error.type.includes('invalid_account')) {
    +   console.log(error.error.detail)
    +   console.log(`Trace ID: ${error.error.trace_id}`)
    + }
    ```
  </Step>
  
  <Step title="Update OAuth Scopes">
    **Use granular permissions**
    
    ```diff
    // Before (v1.3.x)
    - scope: "accounts payments"
    
    // After (v2.0.0)
    + scope: "accounts:read accounts:detail payments:write"
    ```
  </Step>
</Steps>

## FAQ: API Versioning

<AccordionGroup>
  <Accordion title="How long are API versions supported?">
    - **Current versions**: Supported indefinitely
    - **Previous stable**: Minimum 24 months after deprecation
    - **Legacy versions**: 24 months notice before end-of-life
    - **Security patches**: Available for all supported versions
  </Accordion>
  
  <Accordion title="Can I use multiple API versions simultaneously?">
    Yes, you can mix API versions in the same application. However, we recommend standardizing on the latest version for consistency and future compatibility.
  </Accordion>
  
  <Accordion title="What happens if I don't migrate from deprecated versions?">
    - **After deprecation**: No new features, security patches only
    - **After end-of-life**: No support, potential service termination
    - **Grace period**: 6-month extended support available (fee-based)
  </Accordion>
  
  <Accordion title="Are there any costs associated with API versioning?">
    - **Migration tools**: Free for all customers
    - **Self-service migration**: No additional costs
    - **Professional services**: Custom pricing available
    - **Extended support**: Fee-based for end-of-life versions
  </Accordion>
</AccordionGroup>

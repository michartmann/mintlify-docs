## API Categories

### Customer Data Platform (CDP)
Access unified customer profiles, analytics, and insights for personalized banking experiences.

**Key Features:**
- 360° customer view aggregation
- Real-time behavioral analytics
- ML-powered predictions
- Advanced customer segmentation

[Explore CDP APIs →](/api-reference/cdp-overview)

### Third-Party Provider (TPP) APIs
CBUAE-compliant Open Banking APIs for Account Information Service Providers (AISPs) and Payment Initiation Service Providers (PISPs).

**Key Features:**
- Account information access
- Payment initiation services
- Confirmation of Payee verification
- Product information catalog

[Explore TPP APIs →](/api-reference/tpp-overview)

### Licensed Financial Institution (LFI) APIs
Enhanced APIs for banks and licensed financial institutions with advanced integration capabilities.

**Key Features:**
- Advanced consent management
- Headless authentication services
- Real-time event streaming
- Bi-directional data sharing
- Insurance data integration

[Explore LFI APIs →](/api-reference/lfi-overview)

## API Standards

ADCB APIs follow international Open Banking standards and best practices:

<Tabs>
  <Tab title="Security Standards">
    - **OAuth 2.0** for authentication and authorization
    - **mTLS** (mutual TLS) for transport security
    - **JWS** (JSON Web Signature) for message integrity
    - **FAPI** (Financial-grade API) compliance
    - **PCI DSS** Level 1 certified infrastructure
  </Tab>
  <Tab title="Technical Standards">
    - **REST** architectural style
    - **JSON** request/response format
    - **OpenAPI 3.0** specifications
    - **ISO 20022** message formats
    - **UTF-8** character encoding
  </Tab>
  <Tab title="Banking Standards">
    - **CBUAE** Open Banking compliance
    - **IBAN** account identification
    - **BIC/SWIFT** for international transfers
    - **ISO 4217** currency codes
    - **PSD2** regulatory alignment
  </Tab>
</Tabs>

## Common Headers

All API requests must include these standard headers:

```http
Authorization: Bearer {access_token}
Accept: application/json
Content-Type: application/json
X-Request-ID: {unique_request_id}
X-Customer-IP: {end_user_ip_address}
User-Agent: {your_application_name}
```

### Optional Headers

```http
X-Idempotency-Key: {idempotency_key}    # For POST/PUT/PATCH requests
X-JWS-Signature: {jws_signature}        # For sensitive operations
X-Customer-User-Agent: {customer_ua}    # Customer's browser/app info
Accept-Language: en-US,ar-AE            # Preferred language
```

## Error Handling

ADCB APIs use standard HTTP status codes and provide detailed error information:

<AccordionGroup>
  <Accordion title="4xx Client Errors">
    - **400 Bad Request** - Invalid request format or parameters
    - **401 Unauthorized** - Invalid or expired access token
    - **403 Forbidden** - Insufficient permissions or IP not whitelisted
    - **404 Not Found** - Resource not found
    - **409 Conflict** - Request conflicts with current resource state
    - **422 Unprocessable Entity** - Valid format but semantic errors
    - **429 Too Many Requests** - Rate limit exceeded
  </Accordion>
  
  <Accordion title="5xx Server Errors">
    - **500 Internal Server Error** - Unexpected server error
    - **502 Bad Gateway** - Upstream service error
    - **503 Service Unavailable** - Temporary service outage
    - **504 Gateway Timeout** - Upstream service timeout
  </Accordion>
</AccordionGroup>

## Pagination

Large result sets are paginated using cursor-based pagination:

```http
GET /v1/transactions?limit=20&cursor=eyJpZCI6MTIzNDU2fQ==
```

**Parameters:**
- `limit` - Number of items per page (max 100, default 20)
- `cursor` - Opaque cursor for next page

**Response includes pagination metadata:**

```json
{
  "data": [...],
  "pagination": {
    "hasNext": true,
    "hasPrev": false,
    "nextCursor": "eyJpZCI6MTIzNDU2fQ==",
    "prevCursor": null
  }
}
```

## Idempotency

POST and PUT requests support idempotency to prevent duplicate operations:

```http
POST /v1/payments
X-Idempotency-Key: unique-key-12345
Content-Type: application/json

{
  "amount": {"value": 1000, "currency": "AED"},
  "creditorAccount": "AE070331234567890123456"
}
```

- Use unique idempotency keys for each request
- Keys expire after 24 hours
- Duplicate requests return original response
